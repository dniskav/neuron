# Tasks: api-hardening

**Input**: `specs/005-api-hardening/spec.md`, `plan.md`
**Formato**: `- [ ] T0NN [P?] [H|S] [files: ...]` + línea `Gate:`. `[P]` solo si los archivos no se solapan con otras tareas `[P]` del mismo lote. `package.json`, `package-lock.json`, `src/index.ts`, el changelog y `tasks.md` son exclusivos del orquestador. Cada tarea solo toca los archivos de su `[files]`. Ningún agente ejecuta `npm publish` ni sube a `master`. `[H]` = agente `api-dev` o `test-writer` (Haiku); `[S]` = `api-dev` con `model sonnet` o `math-dev`.
**Requisitos de cada agente**: comprobar la base (`git merge-base --is-ancestor fix/v0.4 HEAD`; si no, `git rebase fix/v0.4`), `npm ci` si falta `node_modules`, comandos git simples (sin `cd && git` ni `for`) y NO ejecutar `vitest` en bucle: un solo archivo mientras se itera, la carpeta completa solo al final. En macOS `wc -l` imprime espacios: usar `tr -d ' '`. Scripts temporales en el scratchpad con nombre ÚNICO por tarea (`t0NN_<tema>_<n>.mjs`): el scratchpad es compartido y otro agente puede pisar un nombre genérico.
**GC (gate común)**, que se repite en cada tarea: `npm run typecheck && npx vitest run tests/oracle && git diff --quiet -- package.json package-lock.json src/index.ts`. La definición de terminado (`npx tsc --noEmit -p .`, `npm run build`, `npx vitest run`) la comprueba el `verifier` en la integración.
**Falla antes / pasa después (FR-016)**: tras escribir los tests nuevos y el cambio, el agente demuestra que el archivo nuevo FALLA sin el cambio con tres comandos simples: `git stash push -- <los archivos src de la tarea>`, `npx vitest run <archivo nuevo>` (debe fallar; anotar el mensaje en una línea), `git stash pop`. Los tests de error comprueban el TEXTO (`toThrow(/Clase\.método.*longitud|length/)`), no solo que lancen, y que el estado del modelo (`getWeights()` o pesos relevantes) no cambió tras el error.
**Golden (trayectoria válida intacta)**: antes de tocar `src/`, capturar con la base un resultado numérico pequeño (pesos tras 3 pasos con semilla fija, o salida de `forward`) y fijarlo en el test como constantes con tolerancia 1e-9, o escribir en el test una réplica del algoritmo antiguo y comparar con `toEqual`. Debe seguir pasando tras el cambio, salvo en lo declarado en Q4, Q7, Q8 y Q9.
**Mutante (Constitución IV)**: quitar o ALTERAR temporalmente CADA término/validación listado (no solo invertir), comprobar que el archivo de tests FALLA, restaurar con `git checkout -- src` y repetir el gate. El informe dice en una línea qué mutantes mataron y cuál no.
**Tests de aprendizaje robustos (lección CI)**: los tests de "aprende" (T007, T011, T014) se validan con `lr` ×0.7 y ×1.3 y ≥ 5 semillas; el peor caso queda por debajo de `0.7 ×` el umbral; las cifras van en la cabecera del test. Un test de entrenamiento no puede depender de un umbral caótico.
**Orden de lotes**: máximo 4 agentes a la vez. Las tareas que dependen de una pregunta Q del spec no se lanzan hasta que el usuario la resuelva: T004 (Q12), T006 (Q11), T007 (Q5), T008 y T009 (Q4), T011 (Q1, Q2, Q3), T012 (Q6), T013 (Q10), T014 (Q7), T015 (Q9), T016 (Q8). T001–T003 y T005 no dependen de ninguna.
