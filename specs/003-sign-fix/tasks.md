# Tasks: sign-fix

**Input**: `specs/003-sign-fix/spec.md`, `plan.md`
**Formato**: `- [ ] T0NN [P?] [H|S] [files: ...]` + línea `Gate:`. `[P]` solo si los archivos no se solapan con otras tareas `[P]` del mismo lote. `package.json`, `package-lock.json`, `src/index.ts`, el changelog y `tasks.md` son exclusivos del orquestador. Cada tarea solo toca los archivos de su `[files]`. Ningún agente ejecuta `npm publish` ni sube a `master`.
**Requisitos de cada agente**: comprobar la base (`git merge-base --is-ancestor fix/v0.4 HEAD`, si no, `git rebase fix/v0.4`), `npm ci` si falta `node_modules`, y usar comandos git simples (sin `cd && git` ni `for`).
**Gate común** (se repite en cada tarea de modelo con el nombre sustituido): (1) el oráculo del modelo, (2) `npm run typecheck`, (3) `npx vitest run tests/oracle` para ver que no se rompen los demás oráculos, (4) `git diff --quiet -- package.json package-lock.json src/index.ts`. La definición de terminado de la constitución (`npx tsc --noEmit -p .`, `npm run build`, `npx vitest run`) la comprueba el `verifier` en la integración.
**Mutante** (Constitución IV, en todas las tareas S de modelo): tras dejar el test en verde, deshacer temporalmente el arreglo en `src/` (devolver el signo, o mover `update` antes de `dX`), comprobar que el archivo de oráculo FALLA, restaurar el arreglo y repetir el gate. El informe lo dice en una línea.
**Quitar `it.fails` y control**: el `it.fails` del modelo pasa a `it`, el control de signo (test que niega Δw) se borra, el humo y `expectLearns` se conservan y la cabecera del archivo se actualiza si cabe.
**Orden dentro de un lote**: máximo 4 agentes a la vez. Los lotes 2 y 3 requieren T001 integrado en `fix/v0.4`.
