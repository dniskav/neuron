# Tasks: models-fix

**Input**: `specs/004-models-fix/spec.md`, `plan.md`
**Formato**: `- [ ] T0NN [P?] [H|S] [files: ...]` + línea `Gate:`. `[P]` solo si los archivos no se solapan con otras tareas `[P]` del mismo lote. `package.json`, `package-lock.json`, `src/index.ts`, el changelog y `tasks.md` son exclusivos del orquestador. Cada tarea solo toca los archivos de su `[files]`. Ningún agente ejecuta `npm publish` ni sube a `master`.
**Requisitos de cada agente**: comprobar la base (`git merge-base --is-ancestor fix/v0.4 HEAD`, si no, `git rebase fix/v0.4`), `npm ci` si falta `node_modules`, comandos git simples (sin `cd && git` ni `for`) y no ejecutar `vitest` en bucle: un solo archivo de oráculo mientras se itera, la carpeta completa solo al final. En macOS `wc -l` imprime espacios: usar `tr -d ' '`.
**Gate común** (se repite en cada tarea de modelo con el nombre sustituido): (1) el oráculo del modelo y el test de unidad afectado, (2) `npm run typecheck`, (3) `npx vitest run tests/oracle`, (4) `git diff --quiet -- package.json package-lock.json src/index.ts`, y (5) que el archivo del modelo ya no contenga `it.fails` ni `AUDIT <id>` abierto. La definición de terminado (`npx tsc --noEmit -p .`, `npm run build`, `npx vitest run`) la comprueba el `verifier` en la integración.
**Mutante** (Constitución IV, FR-010): tras dejar el test en verde, quitar temporalmente CADA término listado en la tarea (no solo invertir el signo), comprobar que el archivo de oráculo FALLA, restaurar con `git checkout -- src` y repetir el gate. El informe dice en una línea qué mutantes mataron y cuál no. Las constantes globales que el coseno no ve (factor 2, `(1−D)`, `2/d`) se cubren con `ratio` o con comparación exacta por componente.
**Tests de aprendizaje robustos** (FR-011, lección CI): GAN, VAE y ContrastiveLearning se validan con perturbaciones de `lr` (×0.7 y ×1.3) y de semilla (≥ 5 semillas distintas, más ruido relativo 1e-9 en los pesos iniciales); el peor caso medido debe quedar por debajo de `0.7 ×` el umbral del criterio (margen ≥ 30 %). Las cifras (peor y mejor) van en la cabecera del test.
**Quitar `it.fails` y control**: el `it.fails` del modelo pasa a `it`; se borran los tests que solo valían mientras el defecto existía (excepción, banda parcial, control); el humo y "learns" se conservan; la cabecera del archivo se reescribe.
**Orden de lotes**: máximo 4 agentes a la vez. T005 requiere T001 integrada; T007 y T008 requieren T005 integrada. Las tareas que dependen de una pregunta del spec (Q) no se lanzan hasta que el usuario la resuelva: T001/T005 (Q1, Q2), T002 (Q6), T003 (Q8), T004 (Q9), T006 (Q7), T007 (Q10), T008 (Q3, Q4, Q5).
