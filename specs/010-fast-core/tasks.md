# Tasks: fast-core (010)

**Input**: `spec.md`, `plan.md`, `contracts.md` (firmas exactas: si algo no encaja, `blocked`).
**Formato**: `- [ ] T0NN [P?] [H|S] [agente] [files: ...]`, seguido de una línea `Gate:`. `[H]` Haiku, `[S]` Sonnet. `[P]` solo si los archivos no se solapan con otras `[P]` del mismo lote.
**Archivos exclusivos del orquestador**: `tasks.md`, `package.json`, `package-lock.json`, `src/index.ts`, `CHANGELOG.md` y `AGENTS.md`, salvo en T023, que los autoriza. Si la exportación es una clase entrenable, registrar también su oráculo en `COVERED` de `tests/oracle/coverage.test.ts`. Cuando una tarea crea exportaciones, el orquestador las añade a `src/index.ts` **y** la fila correspondiente a `AGENTS.md` en el mismo commit de integración, para que `tests/docs.agents.exports.test.ts` siga en verde. Lo mismo con el README: `tests/docs.readme.exports.test.ts` exige que cada exportación aparezca en él, así que el orquestador añade una mención y un ejemplo ejecutable en `specs/007-docs/readme-parts/06-nucleo-rapido.md`, regenera con `node specs/007-docs/tools/assemble-readme.mjs` y lo comprueba con `node specs/007-docs/tools/readme-gate.mjs specs/007-docs/readme-parts/06-nucleo-rapido.md --runs 1`. Las rutas de subcarpetas se citan en AGENTS.md desde la raíz (`src/core/optim.ts`).
**Base de cada agente**: el orquestador crea antes un worktree por tarea (`git worktree add .claude/worktrees/010-T0NN -b 010/T0NN feat/0.5-core`) y le da la ruta al agente, que trabaja SOLO dentro de ella (sin `isolation`, porque el worktree automático saldría de `fix/v0.4`). Comprobar `git merge-base --is-ancestor feat/0.5-core HEAD`; si falla, informar `blocked`. `npm ci` si falta `node_modules`. Comandos git simples (sin `cd && git` ni bucles). En macOS `wc -l` imprime espacios: usar `tr -d ' '`.
**Gate común** (se añade a cada tarea con `src/`): `npm run typecheck && npx vitest run && git diff --quiet -- package.json package-lock.json src/index.ts`. Mientras se itera, ejecutar solo los archivos de test de la tarea; la suite completa, una vez al final.
**Mutantes**: cada tarea con `src/` lista sus mutantes. Para cada uno: aplicarlo, comprobar que algún test de la tarea FALLA, revertir con `git checkout -- src` y repetir el gate. El informe dice en una línea cuáles se detectaron.
**Informe**: el formato de `specs/ORCHESTRATION.md` (Tarea, Estado, Rama, Commit, Archivos, Criterio, Pendiente), más las exportaciones que pide añadir a `src/index.ts`.
**Lote 0**: no se lanza ningún agente hasta que el usuario resuelva Q1–Q9 (al menos las que bloquean el lote) y se cree la rama.
